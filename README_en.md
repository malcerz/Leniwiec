# Leniwiec

Leniwiec is an Android app for planning and exporting simple route tracks in GPX format. The current codebase wraps a local HTML/JavaScript interface inside an Android `WebView`, requests device location permissions, and exposes a native share action for generated GPX files.

The app searches for roads with the least elevation gain, and generates loop routes by looking for the route with the fewest climbs

## What the app does

The application loads a bundled web interface from `app/src/main/assets/www/index.html` instead of rendering its main screen with native Compose views. Based on the Android code and packaged web assets, the main goal is to let the user work with route data in the embedded interface and then share the generated GPX file through Android's native share sheet.

## How routes are planned

Routes are calculated **locally on the device** using the bundled BRouter engine (`brouter-lib`) and downloaded segment data (`.rd5`). When local data is not available, the app falls back to the public `brouter.de` API.

### A→B mode

- For points A and B the app requests `N` variants (alternatives) at once (`alternativeidx` 0..N).
- A variant that does not meet the criteria is rejected and the app fetches further alternatives (up to 10) until it gets the requested number of routes.

### Loop mode

- The user provides the loop length (km). BRouter's round-trip mode places soft waypoints on a circle around the start point and snaps them to nearby flat infrastructure.
- The circle radius is ~1/5 of the requested length (loop length ≈ 5× radius), minimum 500 m.
- Variants are generated by rotating the start angle (step 360°/N, offset +15° between rounds, up to 36 angles).
- Computation time scales with route length: ~30 s per 10 km (min. 20 s) per variant, and the whole series has a hard 6-minute cap — the UI always finishes.

### Criteria and scoring (Phase 2)

Each generated candidate is evaluated and may be rejected when it does not meet the criteria:

- elevation gain ≤ 15 m per route km,
- self-overlap ≤ 10 % of the route length,
- for loops: length within ±40 % of the requested one.

Rejected routes do not count toward the result — the search is repeated until the requested number of variants is collected. If, in very hilly terrain, no route meets the criteria, the best rejected candidates are shown instead.

The remaining candidates are sorted by score:

```
Score = 1·|length − requested length| + 2·total ascent + 1·overlap [m]
```

The route with the smallest elevation gain ("Flattest") is always placed first on the list.

## Current architecture

- Android app written in Kotlin.
- UI container created with Jetpack Compose.
- Main functionality displayed inside a `WebView`.
- Local web frontend built with HTML, CSS, and JavaScript.
- Offline route calculation through the bundled BRouter engine (`brouter-lib`).
- GPX export handled through a JavaScript-to-Android bridge.
- Secure file sharing implemented with `FileProvider`.

## Technical details

The project uses Android SDK 36, minimum SDK 24, Java 17, and Jetpack Compose with Material 3 dependencies. The manifest also enables internet access and coarse/fine location permissions, which matches a route-oriented or map-oriented mobile app.

Every build automatically increments the version counter in `app/version.properties` (version `1.00XX`), shown in the app next to the "Leniwiec" name.

## Build and run

### Android Studio

1. Clone the repository:

```bash
git clone https://github.com/malcerz/Leniwiec.git
cd Leniwiec
```

2. Open the project in Android Studio.
3. Wait for Gradle sync to finish.
4. Run the `app` module on an emulator or Android device.

### Command line

Build a debug APK with:

```bash
./gradlew assembleDebug
```

On Windows:

```powershell
gradlew.bat assembleDebug
```

The generated APK should appear in:

```
app/build/outputs/apk/debug/
```

For convenience, the pre-compiled debug APK is also copied to the repository root as [app-debug.apk](file:///f:/_DEV/Leniwiec/app-debug.apk) and to the assets folder as [app/src/main/assets/app-debug.apk](file:///f:/_DEV/Leniwiec/app/src/main/assets/app-debug.apk).

A release build can be produced with `gradlew.bat assembleRelease`; the resulting `app/build/outputs/apk/release/app-release.apk` is also copied to the repository root as `app-release.apk`.

## Permissions

The app currently declares the following permissions:

- `INTERNET`
- `ACCESS_FINE_LOCATION`
- `ACCESS_COARSE_LOCATION`

These permissions are consistent with an app that can work with location-aware route data and potentially web-based map components.

## Current status

The app is under active development and works fully offline thanks to the bundled BRouter engine (`brouter-lib`) — routes are calculated on the device without external servers (except geocoding and the online fallback for route fetching). The project is developed on GitHub. The code still uses the temporary package id `com.example.leniwiec`.

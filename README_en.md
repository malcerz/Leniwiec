# Leniwiec

Leniwiec is an Android app for planning and exporting simple routes in GPX format. The current app code embeds a local HTML/JavaScript interface inside a `WebView` component, requires the device's location permissions, and provides a native sharing action for the generated GPX file.
The app searches for roads with the smallest number of elevation gains, and generates loop routes by looking for the route with the fewest climbs.

## What the app does

The app loads a built-in web interface from the file `app/src/main/assets/www/index.html` instead of rendering the main screen using native Compose views. Based on the Android code and the bundled web assets, it can be inferred that the main purpose is to let the user work with route data in the embedded interface, and then share the generated GPX file through Android's native share dialog.

## How routes are calculated

Routes are calculated **locally on the device** using the built-in BRouter engine (`brouter-lib`) and downloaded segment data (`.rd5`). When local data is unavailable, the app falls back to the public `brouter.de` API.

### A→B mode

- For points A and B, the app requests `N` variants (alternatives) from BRouter simultaneously (`alternativeidx` 0..N).
- A variant that doesn't meet the criteria is rejected, and the app fetches further alternatives (up to 10) until it obtains the required number of routes.

### Loop mode

- The user specifies the loop length (km). BRouter, in round-trip mode, distributes soft route points on a circle around the starting point and fits them to nearby flat infrastructure.
- The circle radius is ~1/5 of the specified length (loop length ≈ 5× radius), min. 500 m.
- Further variants are generated by rotating the starting angle (step of 360°/N, with a 15° offset between rounds, up to 36 angles).
- Computation time scales with route length: ~30 s per 10 km (min. 20 s) per variant, and the entire batch has a hard limit of 6 minutes — the interface always finishes its work.

### Criteria and scoring (Phase 2)

Each generated candidate is evaluated and may be rejected if it doesn't meet the criteria:

- elevation gain ≤ 15 m per km of route,
- route self-overlap ≤ 10% of length,
- for loops: length within ±40% of the specified value.

These thresholds can be adjusted in the app: sliders icon in the header → "Route Settings." Changes are saved on the device and used for subsequent calculations.

Rejected routes don't count toward the result — the search is repeated until the required number of variants is collected. If, in very hilly terrain, no route meets the criteria, the best of the rejected ones are shown.

The remaining candidates are sorted by score:

```
Score = 1·|length − target length| + 2·total climbs + 1·overlap [m]
```

The route with the smallest elevation gain ("Flattest") is always placed first on the list.

## Current architecture

- Android app written in Kotlin.
- UI container built with Jetpack Compose.
- Main functionality displayed inside a `WebView`.
- Local web frontend built with HTML, CSS, and JavaScript.
- Local offline route calculation via the built-in BRouter engine (`brouter-lib`).
- GPX export handled via a JavaScript–Android bridge.
- Secure file sharing implemented using `FileProvider`.

## Technical details

The project uses Android SDK 36, minimum SDK 24, Java 17, and Jetpack Compose with Material 3 dependencies. The app manifest also enables internet access and location permissions (fine and coarse), which is consistent with a route- or map-oriented app.

Each build automatically increments the version counter in `app/version.properties` (version `1.00XX`), displayed in the app next to the name "Leniwiec."

## Building and running

### Android Studio

1. Clone the repository:

```bash
git clone https://github.com/malcerz/Leniwiec.git
cd Leniwiec
```

2. Open the project in Android Studio.
3. Wait for Gradle sync to finish.
4. Run the `app` module on an emulator or an Android device.

### Command line

Build the debug APK with:

```bash
./gradlew assembleDebug
```

On Windows:

```powershell
gradlew.bat assembleDebug
```

The generated APK file should appear at:

```
app/build/outputs/apk/debug/
```

For convenience, the compiled APK file is also copied to the repository's root directory as [app-debug.apk](file:///f:/_DEV/Leniwiec/app-debug.apk) and to the assets folder as [app/src/main/assets/app-debug.apk](file:///f:/_DEV/Leniwiec/app/src/main/assets/app-debug.apk).

The release version can be built with `gradlew.bat assembleRelease`; the resulting `app/build/outputs/apk/release/app-release.apk` file is also copied to the repository's root directory as `app-release.apk`.

## Permissions

The app currently declares the following permissions:

- `INTERNET`
- `ACCESS_FINE_LOCATION`
- `ACCESS_COARSE_LOCATION`

These permissions are consistent with an app that may operate on location-dependent route data and potentially use web-based map components.

## Current status

The app works fully locally (offline) thanks to the built-in BRouter engine (`brouter-lib`) — routes are calculated on the device, without external servers (except for geocoding and the emergency online route fallback). The project is being developed on GitHub.
